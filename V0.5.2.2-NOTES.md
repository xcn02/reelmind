# ReelMind 0.5.2.2 — Extraction JSON + yt-dlp

## Changements
- Dans Réglages > Extraction hybride : choix du moteur de métadonnées : automatique (JSON → yt-dlp → Render), yt-dlp seul (mécanique historique V0.5.1), JSON seul. La lecture JSON n'utilise ni clé API ni cookies.
- En mode automatique, les champs de métadonnées absents sont complétés sans écraser les champs déjà obtenus. La transcription audio peut toujours déclencher le téléchargement temporaire via yt-dlp.
- Métadonnées : légende originale distincte, auteur, miniature. Diagnostic par méthode visible dans la section Analyse des fiches.
- Titre provisoire : première phrase nettoyée de la légende (max. 100 caractères, sans couper les mots). Aucun changement rétroactif des anciennes fiches.
- Après analyse IA : si la réponse contient une ligne « Titre: ... », celle-ci peut remplacer le titre provisoire. Un titre modifié manuellement reste prioritaire et n'est jamais écrasé.
- Les anciennes fiches sont conservées. Migration Room 5 vers 6 avec champs manualTitle et extractionDiagnostic.
- Aucun retry IA automatique n'est introduit. Les boutons téléchargement/partage/Instagram et le bouton + catégorie de 0.5.2.1 sont conservés.
- versionCode 9 ; applicationId et clé de signature inchangés dans le projet.

## Limites et tests indispensables
- La récupération JSON des pages publiques dépend du HTML qu'Instagram renvoie ; elle peut échouer. Dans ce cas, utiliser Automatique ou yt-dlp seul.
- Vérifier sur Android trois cas : Reel avec légende, sans légende, et publication inaccessible ; contrôler l'auteur, la miniature, le diagnostic et la génération de titre.
- Vérifier la transcription et une analyse IA en succès et en erreur, sans répétition de requêtes.
- Le projet n'a **pas** été compilé en APK dans cet environnement, faute de SDK Android/Gradle. Construire via GitHub Actions puis tester sur un appareil.
- Éviter d'importer le code GPLv3 d'InstaDownload : le parseur JSON ajouté a été rédigé indépendamment après étude de son fonctionnement général.
